# Курсовая работа на тему Reinforcement learning: DQN на простой среде.

## 1. Цель

Разработать среду и обучить DQN-агента проезжать из точки А в точку Б по заранее построенному маршруту за минимальное время при соблюдении формализованных правил движения. Агент управляет газом, торможением и рулением и завершает поездку остановкой в зоне Б.

## 2. Территория и границы задачи

Двумерная городская среда с видом сверху моделирует участок Санкт-Петербурга:

| Граница | Координата WGS 84 |
| --- | ---: |
| Север | 59.96915 |
| Юг | 59.95131 |
| Запад | 30.28802 |
| Восток | 30.32390 |

Базовая версия содержит один автомобиль, дороги, полосы, знаки, пешеходные переходы и работающие светофоры. Другой транспорт, пешеходы, погода и сложная динамика сцепления не моделируются. Светофоры используют программы симуляции, а не реальные текущие сигналы города. Проверяется выбранный набор правил, а не соответствие всем ПДД.

## 3. Исходные данные

Основной источник - OpenStreetMap через Overpass Turbo. Основной файл - `export.json` - экспорт из Overpass Turbo, в котором находится вся информация о моделируемом участке города.

Выгрузка должна содержать:

- автомобильные дороги и их геометрию;
- доступные атрибуты скорости, направлений, доступа, полос и манёвров;
- отношения ограничений поворотов;
- светофоры, знаки STOP, объекты с `traffic_sign`;
- точки переходов и линии `highway=footway` + `footway=crossing`;
- адресные объекты с `addr:street` и `addr:housenumber`.

### Подготовка данных

| Код | Требование |
| --- | --- |
| DATA-01 | Прочитать исходные объекты с сохранением типа, координат и тегов |
| DATA-02 | Отобрать дороги с учётом доступа для моделируемого автомобиля |
| DATA-03 | Построить направленный граф с ограничениями поворотов |
| DATA-04 | Подготовить границы дорог, полосы и соединения полос на перекрёстках |
| DATA-05 | Привязать стоп-линии, светофоры и знаки к конкретным направлениям и участкам |
| DATA-06 | Хранить ручные дополнения отдельно от неизменённых исходных выгрузок |

## 4. Координаты и единицы

| Величина | Представление |
| --- | --- |
| Исходная география | WGS 84, градусы |
| Проекция | WGS 84 / UTM zone 36N, EPSG:32636 |
| Координаты среды | Локальные x, y в метрах относительно фиксированного начала |
| Габариты и расстояния | Метры |
| Время | Секунды |
| Скорость | М/с в расчётах; км/ч в интерфейсе |
| Ускорение | М/с² |
| Углы и угловая скорость | Радианы и рад/с |
| Отображение | Пиксели |

Локальные координаты вычисляются вычитанием фиксированного начала из координат UTM. Ось x направлена на восток, y - на север. Нулевое направление автомобиля - восток, положительное вращение - против часовой стрелки. Масштаб отображения не влияет на физику. Все объекты используют одно преобразование координат.

## 5. Адреса и маршрут

| Код | Требование |
| --- | --- |
| ROUTE-01 | Задание А и Б адресом с подсказками либо кликом по карте |
| ROUTE-02 | Локальный поиск адресов по выгруженным атрибутам |
| ROUTE-03 | Привязка адреса к подходящему доступному дорожному участку, а не к центру здания |
| ROUTE-04 | Поиск кратчайшего по длине разрешённого маршрута |
| ROUTE-05 | Учёт односторонности, доступа и ограничений переходов между дорогами |
| ROUTE-06 | Сообщение об отсутствующем адресе, выходе за границы или отсутствии пути |
| ROUTE-07 | Передача маршрута в виде направленных участков и геометрии пути по разрешённым полосам |

Предпочтительный алгоритм - A*. Дейкстра допускается как базовая реализация для сравнения. Эвристика A* - расстояние по прямой в метрической системе, согласованной с длинами рёбер. Ограничения поворотов требуют учёта входящего ребра, а при необходимости последовательности участков.

Маршрутизатор определяет путь, но не управляет автомобилем. Кратчайший маршрут по длине не обязательно является самым быстрым с учётом светофоров. DQN минимизирует время прохождения заданного пути.

## 6. Автомобиль и физика

Состояние автомобиля включает координаты, направление корпуса, скорость, угол передних колёс и габариты. Движение рассчитывается по упрощённой модели с ограниченными ускорением, торможением, углом и скоростью поворота колёс.

| Код | Требование |
| --- | --- |
| CAR-01 | Свободное движение по плоскости, включая возможность ошибки и выезда с дороги |
| CAR-02 | Полное управление педалями и рулением со стороны DQN |
| CAR-03 | Отсутствие автоматического удержания полосы, привязки к маршруту и выполнения поворотов |
| CAR-04 | Отсутствие принудительного торможения на красный и обрезания скорости дорожным лимитом |
| CAR-05 | Проверки положения с учётом габаритов, а пересечения стоп-линии - передней части автомобиля |
| CAR-06 | Фиксированный шаг модельного времени, независимый от частоты отображения |

Физические пределы автомобиля сохраняются: запрет автоматического ограничения дорожным лимитом не отменяет максимальную техническую скорость.

## 7. Наблюдения агента

Базовый вариант - числовой вектор фиксированной размерности и полносвязная нейросеть MLP.

| Группа | Предлагаемые признаки |
| --- | --- |
| Автомобиль | Скорость, угол передних колёс |
| Положение | Отклонение от нужной полосы, разница направлений машины и полосы |
| Дорога впереди | Фиксированное число точек маршрута относительно машины, расстояния до границ |
| Светофор | Наличие, текущий сигнал, расстояние до соответствующей стоп-линии |
| Ограничения | Текущий лимит скорости; при необходимости ближайшее изменение |
| STOP | Наличие, расстояние и состояние выполнения остановки |
| Цель | Оставшееся расстояние по маршруту и положение относительно зоны Б |

Числовые признаки нормализуются, категории кодируются индикаторами, отсутствие объектов обозначается явно. Наблюдение должно содержать достаточно информации для поворота, остановки и определения финиша. Готовые команды и будущие сигналы светофоров не передаются.

Окончательный состав и размер вектора устанавливаются при реализации. При управлении приращениями необходимо включить текущие положения управляющих органов, от которых зависят следующие действия.

## 8. Пространство действий

Стандартный DQN использует конечный фиксированный набор. Начальная версия - 9 комбинаций:

| ID | Педали | Руление |
| --- | --- | --- |
| 0 | Накат | Прямо |
| 1 | Накат | Влево |
| 2 | Накат | Вправо |
| 3 | Газ | Прямо |
| 4 | Газ | Влево |
| 5 | Газ | Вправо |
| 6 | Тормоз | Прямо |
| 7 | Тормоз | Влево |
| 8 | Тормоз | Вправо |

Руление задаёт целевой угол колёс. «Прямо» означает нулевой угол, а не выравнивание относительно дороги. Накат означает отсутствие газа и тормоза и не гарантирует сохранение скорости. Команда выполняется до следующего решения; приводы имеют ограниченную скорость изменения.

Точные углы, интенсивности педалей и интервал решений не утверждены. Интервал 0.1 с - кандидат для экспериментов. Допускается исследование большего числа уровней или управления приращениями.

## 9. Правила и светофоры

Среда должна регистрировать:

- превышение действующего ограничения скорости;
- пересечение стоп-линии на запрещающий сигнал;
- невыполнение остановки перед STOP;
- выезд за разрешённую область дороги;
- движение по встречному направлению;
- отклонение от заданного маршрута.

Программы светофоров задают последовательность фаз, длительности, начальную фазу и соответствие сигналов подъездам и манёврам.

Красный и жёлтый запрещают въезд. Для жёлтого необходимо формализовать возможность остановки по скорости, расстоянию и допустимому замедлению. Законный въезд не становится нарушением из-за смены сигнала после пересечения стоп-линии. Одно пересечение фиксируется как одно событие нарушения.

Переходы отображаются, перед пешеходными переходами агент должен всегда сбавлять скорость.

## 10. Эпизод и функция награды

Эпизод - попытка проехать от А до Б. В начале автомобиль размещается на допустимой полосе с согласованным направлением и нулевой скоростью. Успешное завершение требует прохождения маршрута и остановки в зоне Б без нарушений.

| Составляющая | Назначение |
| --- | --- |
| Продвижение по маршруту | Поощрение движения к цели |
| Стоимость модельного времени | Сокращение лишнего ожидания и манёвров |
| Штрафы за нарушения | Поощрение соблюдения правил |
| Награда за прибытие и остановку | Завершение задачи |

Прогресс оценивается вдоль маршрута с учётом порядка участков. Срезание вне дороги и повторное движение туда-обратно не должны давать выгодную дополнительную награду. Ожидание на красный увеличивает время, но не считается отдельным неправильным простоем.

Коэффициенты награды задаются конфигурацией и подбираются экспериментально. Необходимо проверять, что агент не выбирает постоянную стоянку или нарушения ради выигрыша времени.

## 11. Алгоритм обучения

DQN должен включать основную Q-сеть, целевую сеть, буфер опыта, ε-жадное исследование и обновления на случайных пакетах переходов. Сеть выдаёт Q-оценку каждого действия. Модель, параметры нормализации, конфигурация действий и настройки эксперимента сохраняются совместно.

Последовательность усложнения сценариев:

1. Прямая дорога: движение и удержание полосы.
2. Повороты: руление и выбор скорости.
3. Перекрёстки: исполнение маршрута.
4. Светофор и STOP: остановка и возобновление движения.
5. Несколько перекрёстков и разные пары А и Б.

На всех этапах руление и педали контролирует агент. Маршруты и начальные фазы для итогового тестирования отделяются от обучающих сценариев. Оценка проводится без исследовательских случайных действий и с несколькими запусками обучения.

## 12. Интерфейс среды

Предусмотрены операции `reset`, `step`, `render`, `close`.

Результат шага содержит наблюдение, награду, признаки завершения и усечения, диагностическую информацию. Правила и физика одинаковы при включённой и отключённой визуализации.

| Режим | Требования |
| --- | --- |
| Обучение | Без окна и рендера при числовом входе; без ожидания реального времени |
| Демонстрация | Отображение карты и движения в масштабе времени 1:1 с возможностью изменения скорости |
| Отладка | Просмотр геометрии, свойств объектов, событий и составляющих награды |

В окне показываются маршрут, автомобиль, полосы, знаки, светофоры, стоп-линии, переходы, А и Б. Панель отображает скорость, действие, прогресс, награду и нарушения. Доступны запуск, пауза, сброс и выбор начальных условий.

Одинаковые данные, конфигурация, seed и действия должны воспроизводить одинаковый эпизод среды. Все параметры и изменения ручной разметки должны быть сохраняемыми.

## 13. Проверка и метрики

### Проверка среды до обучения

| Сценарий | Ожидаемый результат |
| --- | --- |
| Разгон, торможение, руление | Изменения соответствуют физическим ограничениям |
| Выезд с дороги | Фиксируется с учётом габаритов автомобиля |
| Пересечение стоп-линии на красный | Одно нарушение за пересечение |
| Ожидание перед красным | Нарушение отсутствует |
| Смена сигнала после законного въезда | Не создаёт нарушения задним числом |
| Превышение скорости | Фиксируется, но не устраняется автоматически |
| Запрещённый поворот | Исключён из маршрута и обнаруживается при исполнении |
| Адрес внутри здания | Старт или финиш привязывается к подходящей дороге |
| Остановка в зоне Б после прохождения маршрута | Регистрируется достижение цели |
| Истечение времени | Возвращается признак усечения |
| Повтор одинакового сценария | Воспроизводятся состояния и события |

### Метрики агента

- доля достижений Б;
- доля завершённых поездок без нарушений - главная метрика;
- время успешных поездок;
- сравнение времени поездки с ожидаемым временем в лучшем и худшем случае относительно светофоров, знаков STOP и пешеходных переходов;
- нарушения по типам;
- длительность и максимальная величина превышения скорости;
- доля пройденного маршрута для незавершённых поездок;
- суммарная награда и её динамика.
